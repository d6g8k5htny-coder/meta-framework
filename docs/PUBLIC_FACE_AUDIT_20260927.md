# Public-face navigation audit — 2026-09-27

**Scope:** what a first-time visitor sees on `github.com/d6g8k5htny-coder`, its ten repositories, and the GitHub Pages site — descriptions, READMEs, links, badges, licences, pins. **Not in scope:** any mathematics or status. Scientific effect: **NONE**.

**Method.** Every repository was cloned at its default tip. All 3,376 link references in every Markdown file of every repository (2,679 distinct URLs) plus every link on the two live site pages were requested and their HTTP status recorded. The profile, repository list, each repository landing page and both site pages were then opened in a normal browser as an anonymous visitor. Repository settings (description, homepage, topics, licence, pins) were read through the public API.

## The intent every public surface should serve

The owner's stated intent (2026-09-27): **everything that supports the legitimacy of the work is public and easy to see — above all the mathematical work itself.** Legitimacy here is earned in a specific way: full proof texts rather than summaries; exact source identities (commit, path, bytes, SHA-256) rather than labels; every result stated at its own scope with its parent dependencies named; author derivations, same-author replays and non-author reviews recorded as separate facts; and failed probes and counterexamples kept on record next to the positive results. Openness is the mechanism, not a slogan.

That intent sets the wording rule for every README, description and landing page:

1. **Lead with the mathematics.** The first sentence says what the object is and what it addresses (a coefficient, a remainder bound, a counting theorem, a counterexample), in plain words, with a link to the proof text.
2. **State scope precisely, once.** Hypotheses and what is *not* claimed belong in one clear sentence next to the result — not as a wall of negations before the reader learns what the result is.
3. **Keep internal machinery off the front page.** Batch numbers, `lemma_closed`, token probes, window gates and running logs are real and should stay public, but under `docs/` or a "Change log" heading, not in the first screen a visitor sees.
4. **Make the path obvious.** Every page carries the same header navigation back to `main`, the topic guide, the status snapshot and the reproduction guide; every repository has a one-sentence description and topics; every proof links to its review.
5. **Never trade honesty for polish.** A scoped acceptance stays scoped; an open review stays open; a public sandbox is described as a sandbox.

Where a finding below concerns wording, the fix is judged against these five points.

**Write scope of the auditing agent.** The Cloud Agent App token that produced this audit could push only to `meta-framework` (every other repository returned HTTP 403 on push, and the token cannot edit repository settings). Findings are therefore split into *applied here* and *owed elsewhere*. Items owed elsewhere are written so that any participating model with the relevant write scope, or the owner, can apply them without re-deriving the finding; ready-to-apply copies live under [`portable/`](../portable/).

## Overall

The account is in good shape where it matters most: link health is excellent (only one genuinely broken link in 2,679 distinct URLs), `main` behaves as a real front door with `STATUS.md`, a topic guide, a reproduction guide, a contribution route, `CITATION.cff`, `SECURITY.md`, issue and PR templates, and a live Pages site; `Math-` and `query-` carry the same header navigation so a reader can always get back. The remaining problems are the first-thirty-seconds kind — an unedited profile README, blank or one-word repository descriptions, missing topics and licences on half the repositories — plus a handful of internal inconsistencies that make a careful reader doubt which pin or which contract is current, and some public pages whose first screen is internal machinery rather than the mathematics the account exists to show.

### Finding 3 — sandbox: align the wording with the intent

`sandbox` is public on purpose: exploratory and adversarial experiments, including the ones that fail, are part of the record. What it is *not* is a source of published results, and the catalog tools should keep refusing its paths. The following places still say "private" or imply the repository should be hidden, and should be changed together so no page contradicts another:

| Place | Current text | Proposed text |
|---|---|---|
| `governance-/README.md`, table row and "Privacy and publication" | "Private exploratory and adversarial experiments; no automatic public export" / "Keep `sandbox` private. Do not copy its files … into the public artifact catalog" | "Public exploratory and adversarial experiments, kept on record; not a source of published results" / "`sandbox` is public but is not a results repository. Do not copy its files, outputs, paths or hashes into the public artifact catalog or workflow artifacts; a probe becomes a result only by landing in `Math-` with a review." |

## What good accounts do that this one now does or should

Checked against the conventions used by well-run research and open-source organisations on GitHub: a profile README that states the mission and a start-here path in one screen; every repository with a one-sentence description, topics and a website; a licence file in every repository; consistent header navigation so any page leads back to the front door; CI badges that reflect the default branch; `CITATION.cff`, `CONTRIBUTING.md`, `SECURITY.md` and issue templates on the front door; and a live site. `main`, `Math-` and `query-` already meet most of these; this change brings `meta-framework` into line and records what the remaining repositories still need.
